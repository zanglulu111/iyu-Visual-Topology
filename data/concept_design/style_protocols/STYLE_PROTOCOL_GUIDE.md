# 造型协议词库写法规范

造型协议不是艺术风格、画面风格、人设、职业、时代或场景。它是一套短而强的角色 / 主体概念造型操作协议，用来统摄本体细节如何被解释、吸收和清洗。

## 位置

`时空坐标` 固定现实边界、时代、空间、技术许可。

`身份锚点` 回答主体是谁。

`造型协议` 回答所有可见细节应该如何被角色 / 主体造型化。

`本体细节` 提供年龄、脸、身体、动作、道具等可见参数。

`世界法则` 裁决冲突是写实锁定、同构折译、局部缝合、本体成立，还是狂想接管。

## 标准字段

每个协议词条必须使用同一套字段顺序：

```ts
{
  id: 'cd_proto_route_specific_name',
  name: '中文名',
  group: ROUTE_GROUP,
  groupEn: ROUTE_GROUP_EN,
  def: '中文定义。必须说明统摄方式和视觉签名。',
  defEn: 'English definition. It must explain design governance and visual signatures.',
  ontologyLevel: 1,
  eras: ROUTE_ERAS,
  affects: ['silhouette', 'costume', 'material'],
  risk: 'clean',
  controls: ['concrete_control_key'],
  forbids: ROUTE_FORBIDS,
  absorptionRule: '外来元素如何被吸收。',
  absorptionRuleEn: 'How foreign elements are absorbed.',
  styleRoute: ROUTE
}
```

## 字段含义

`name`
短名，不写长句。它是用户点击时看到的造型协议名。

`def`
两句话以内。第一句说明它如何统摄角色，第二句用“视觉签名”列出可见证据。

`ontologyLevel`
硬许可等级。不是给 AI 算数学，而是给提示词明确现实/超现实边界。

`eras`
该协议天然适合的时代范围。写宽一点，但不要乱写。

`affects`
它主要影响哪些可见层。常用值：
`silhouette`, `costume`, `material`, `symbol`, `prop`, `pose`, `face`, `body`, `wear`, `interface`

`risk`
跑偏风险。
`clean` 表示基本不改变本体。
`medium` 表示可能引入仪式、武装、跨时代或强符号。
`high` 表示可能引入技术义体、生物异化或超现实本体。

`controls`
给程序和提示词看的短控制键。必须具体，不写泛词。

`forbids`
这个协议最容易跑偏的禁区。优先写 3-6 条。

`absorptionRule`
最重要字段。它回答：外来元素、冲突元素、跨场域元素应该被吸收到哪里。

## 写作规则

1. 不写长篇美学散文。
2. 不写场景、镜头、光影、电影感。
3. 不写真实品牌、真实 IP、名人、作品名。
4. 不把职业身份写进造型协议，除非它是造型化制度的一部分。
5. 不把“高定”“街头”“技术”等词只当形容词，要写清楚它们如何改变轮廓、材料、符号、道具或姿态。
6. 每条必须有可见证据。AI 必须能画出来。
7. 每条必须有吸收规则。否则它无法参与融合。

## 好词条标准

好的造型协议词条应该像一把刀：

- 短
- 准
- 有禁区
- 有作用域
- 有可见签名
- 能吸收外来元素
- 能保护身份锚点不被奇观吞掉

## 清洗顺序

先清洗一组到样板质量，再扩数量。

推荐顺序：

1. 高定结构
2. 街头制服
3. 技术装置
4. 武装战术
5. 仪式神圣
6. 贵族礼制
7. 职业功能
8. 废土拼接
9. 生物有机
10. 极简精度

## 扩写数量

每组先扩到 30 条，再测试随机和融合逻辑。

不要直接扩到 100 条。100 条之前必须确认：

- 该组内部没有重复
- 每条的作用域不同
- 随机不会趋同
- 编译提示词不会只拼接标题
- 世界法则能正确处理高风险词条
