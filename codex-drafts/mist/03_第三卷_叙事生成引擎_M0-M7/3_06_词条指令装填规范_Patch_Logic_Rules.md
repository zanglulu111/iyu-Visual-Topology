# M0-M7 引擎词条指令装填规范 (v2.3)

> 本文档定义了“爱欲迷宫”叙事引擎底层词条（M1-M7）结构化指令（`logic`, `patch.runtime`, `patch.aesthetic`）的编写标准。遵循此规范，才能使引擎在抛弃所有“散文体”长篇Prompt的情况下，精确且高效地输出所需极权结构。

## 0. 设计哲学与核心原则

**1. 黑盒断言式：**
系统现在是一个高压微服务架构。不要向AI解释“为什么”，只需要告诉它“是什么”以及“绝对禁止什么”。句子要冷酷、绝对。
**禁忌句式：** “这里描写主体如何如何，展现出他内心的挣扎…” 
**正确指令：** “必须展示主体 [XXX]。严禁出现 [YYY]。”

**2. 层级权限控制**
- `patch.runtime` 是 **「最高优先级硬指令」 (CRITICAL - 物理锁死)**，负责界定绝对红线与行为动作（Do & Don't）。
- `logic` 是 **「叙事骨架机制」 (HIGH - 逻辑断言)**，负责定性在事件流中，当前结构应该呈现怎样的因果关系和拓扑闭环。
- `patch.aesthetic` 是 **「表层美学建议」 (NORMAL - 材质映射)**，负责指引视觉或者文本细节描述的隐喻（可无）。

## 1. M1-M7 词条装填范例与对照标准

目前 `LibraryItemDef` 类型系统中拥有以下三个关键操作字段。使用中文字段即可，如果已有英文可以配套使用：

### 1) `logic` (叙事拓扑逻辑)
**定位：** 机制断定、因果链的闭关法则。
**功能：** 告诉大模型：“这个词条本质上触发了什么哲学/心理学现象？”
**填写标准：** 
- **断言（Assertion）为主：** 采用公理表述。如“主体由于X，必定产生Y”。
- **禁止使用“过程描述”：** 不写“主角慢慢发现自己陷入了深渊”，而写 “【深渊结构】：主体的每一步前进都必然加深其自身匮乏。”

**【示例】: M3_FANTASY (幻象) - “绝对乌托邦”**
```typescript
{
  logic: "【幻象降临】：大他者的禁令被临时悬置，主体与客体a达成虚假的同一。必须表现出一种近乎偏执的狂热与脆弱度，暗示其结构随时会因符号界的反噬而塌陷。"
}
```

### 2) `patch.runtime` (运行时硬指令 / 红线)
**定位：** 最绝对的执行边界。一经挂载，即为天条。
**功能：** 定义该词条出现时的**硬性表现标准**和**绝对禁止的行为**。
**填写标准：**
- **必须使用命令式语句：** “严禁…”、“必须…”、“不论发生什么情况，强制执行…”。
- **包含条件反射限制：** “如果发生A，立刻切断B。” 
- **不留模糊空间。**

**【示例】: M6_PRICE (代价) - “M6.3 认知污染”**
```typescript
{
  patch: {
    runtime: "【代价变现强制执行】：必须以血腥/不可逆的心智损伤为代价结算！**严禁**提供治愈或缓解方案！在M6阶段，主体必然因为跨越禁忌而丧失对现实的认知锚点（必须有具体的幻痛、失语或器官异变描写，严禁使用含糊的心理活动代替）。否则该结构无效！"
  }
}
```

### 3) `patch.aesthetic` (美学修饰映射)
**定位：** 风格化限制与物质还原。
**功能：** 这个词条在“视觉描述”或“文字质感”上应该遵循什么调性？
**填写标准：**
- **侧重感官与色彩：** 提及光影、材质（黏腻、金属反光、雾气等）。
- **具体到意象：** 提供可以被 Midjourney 或视频生成引擎直接映射的视觉词汇。

**【示例】: M4_BIG_OTHER (大他者) - “极权官僚系统”**
```typescript
{
  patch: {
    aesthetic: "视觉必须呈现为灰暗、冷硬的压迫感。材质优先使用剥落的混凝土、生锈的栅栏或无限重复的走廊格子。光线必须是惨白的冷光灯或低沉的无影环境光，严禁出现温暖的逆光或高饱和色彩。文字要求采用公文般冰冷的遣词。"
  }
}
```

## 2. 批量装填清单与工作流建议

目前的痛点是词库（`dataRegistry.ts` 导入的所有 JSON/TS 词条源，比如 M1 到 M7）中有大量数据缺失上述字段，只有基础的 `desc` 或 `def`。

**你需要在这个阶段做的事情：**

1. **选择切入点：** 建议从 **M4 (大他者)** 和 **M6 (代价)** 开始装填。这两个在叙事中的“锁死”作用最强。
2. **迁移与提纯：** 如果一个词条以前在 `def` 里写了很长的文学描述，请将其：
   - 最纯粹的冲突点 提炼到 `logic` 里。
   - 所有的“务必不能”、“决不能” 提炼到 `patch.runtime` 里。
   - 所有环境渲染 提炼到 `patch.aesthetic` 里。
   - 旧的 `def` 适当裁剪即可，不再充当核心判例。
3. **编写脚本辅助（可选）：** 可以用 `mist-engine-lexicon` 或 `mist-lexicon-lacan` Agent Skill 帮你快速转化。给出旧词条，要求它按照以上三要素给你生成 TS 代码端。

## 3. 注意防范机制

- **严禁冲突：** 确保同一词条内 `logic` 和 `patch.runtime` 不要在方向上打架。
- **简短精炼：** `patch.runtime` 应当控制在 50~100 字以内。超过这个长度容易增加幻觉。因为引擎在运行时（`mist_calculator.ts` Line 556-590）会将当前选中的 M1 到 M7 所有 `runtime` 混合加粗高亮注入为 `CRITICAL DICTATES`。
- **无需语法连贯：** 在指令区不需要使用复杂的起承转合。大模型看得懂直接相连的强判断句号。
