# 迷雾学派 哲学辞典 词条补充与撰写指南

这份文档是为 AI 提供的标准规范，用于指导如何为"迷雾学派"哲学辞典系统（Philosophy Codex）补充新的词条数据。

---

## 1. 架构与文件位置

词条数据的增删修改分为以下两个核心步骤：

1. **词条的"户籍"管理（索引注册）**：
   - **位置**：`/data/codex/philosophy_refined.ts`
   - **作用**：定义词条是否存在、ID 标识、以及在列表页展示的简短描述。如果需要合并或重命名词条，必须先在此处修改。
2. **内容的"内脏"填充（详细文本）**：
   - **位置**：`/codex-drafts/[哲学家]/[ID].md`（**新版写作格式，优先使用**）
   - 或旧版：`/public/data/codex/[哲学家]/details/[ID].json`
   - **作用**：存放 1800+1200+1200 格式的硬核长文本。文件名必须与索引中的 ID 严格对应。

---

## 2. 新版写作工作流：Markdown 草稿模式（推荐）

> **重要**：新的标准写作方式是在 `codex-drafts/` 目录下写 `.md` 文件，保存后通过脚本自动转换为 JSON。**AI 应当优先使用这种方式**，而不是直接写 JSON（JSON 中的长文本需要手动转义换行符，极易出错）。

### 文件位置规则

```
codex-drafts/
  lacan/        ← 拉康词条
  hegel/        ← 黑格尔词条
  marx/         ← 马克思词条
  zizek/        ← 齐泽克词条
```

文件命名格式：`[词条ID].md`，例如 `l_mirror_stage.md`。

> 文件名必须与 `philosophy_refined.ts` 中对应词条的 `id` 字段完全一致。

### Markdown 文件格式（必须严格遵守）

文件内容由三个固定区块构成，使用 `##` 二级标题标识：

```markdown
## 定义

[这里写 definition 部分的内容，1800字以上，支持全套 Markdown 排版]

### 1. 哲学史坐标：XXX

正文内容...

**加粗**、*斜体*、列表随意使用，
但请勿在内容中使用 `## 定义`、`## 类比`、`## 应用` 这三个标题
（以免被误判为区块分隔符）。

---

## 类比

[这里写 analogy 部分的内容，1200字以上]

### 1. 第一个类比名称

...

### 2. 第二个类比名称

...

---

## 应用

[这里写 application 部分的内容，1200字以上]

### 迷雾学派创作理论应用

...
```

**三个区块标题的合法写法**（只有这三种会被识别为区块分隔符）：

| 区块 | 标题写法 | 对应 JSON 字段 |
|------|----------|--------------|
| 核心定义 | `## 定义` | `definition` |
| 拓扑类比 | `## 类比` | `analogy` |
| 创作应用 | `## 应用` | `application` |

### 转换命令

写完保存后，运行以下任意一条命令生成 JSON：

```bash
# 监听模式：保存即自动转换（写作时推荐开启）
npm run codex:watch

# 一次性转换所有草稿
npm run codex:build

# 把已有的 JSON 批量导入为 .md 草稿（用于编辑已有词条）
npm run codex:import
```

> 转换脚本位于 `scripts/codex-convert.cjs`，输出至 `public/data/codex/[哲学家]/details/[ID].json`。

## 3. 注册词条索引（TypeScript）

**每新增一个词条，都必须先在索引文件中注册**，否则前端不会显示该词条。

- **文件位置**：`/data/codex/philosophy_refined.ts`
- 找到对应哲学家的 `concepts` 数组，插入如下对象：

```typescript
{
    id: "词条英文ID",         // 例如: "l_mirror_stage"，必须唯一
    name: "中文词条名",       // 例如: "镜像阶段"
    enName: "原文/英文名",    // 例如: "The Mirror Stage"
    category: "所属分类",     // 例如: "RSI" 或 "Methodology"
    shortDef: "一到两句话的精简定义（显示在卡片上）",
    author: "提出者（选填）", // 例如: "Jacques Lacan"
    source: "原文出处（选填）",
    tags: ["TAG1", "TAG2"],  // 标签（选填）
    related: ["关联词条1"]   // 关联词条（选填）
}
```

## 4. 撰写风格与字数要求

**这是一部高度专业、具有极强理论深度的黑核哲学辞典，同时也是为"爱欲迷宫"叙事与电影创作服务的设定集。**

撰写单个词条时，**总字数（含三部分）应保持在 5000 字以上**，以确保分析的透彻度与阅读的压迫感。

在具体撰写前，**AI 必须按优先级查阅以下核心理论文档**，以确保与迷雾学派体系完全吻合：

- **[最高优先级]** `docs/MIST_SCHOOL_THEORY_OVERVIEW.md`（迷雾学派理论总纲，深入理解爱欲迷宫、视差缝合与污迹美学等核心底层逻辑）
- `docs/guides/ADD_PHILOSOPHY_CODEX_GUIDE.md`（本文档，了解各部分的具体撰写规范与字数要求）
- `data/codex/philosophy_refined.ts`（查看词条分类、索引架构与已有哲学体系）
- `data/narrative_engine.ts` 和 `backend/data/whitepaper_data.ts`（深入理解"爱欲视差"、剧作公式组合与核心理论参数）
- `data/narrative_protocols.ts`（叙事协议，包含命名、美学、铁律等实战细节）

### Part 1：核心定义（`## 定义` 区块）

**重点：学术性、原典对读、辩证法深潜。**

> 要求：**不少于 2500 字**。绝不能是百科全书式的简单说教。

- **哲学史坐标**：将该概念置于哲学史的演变中（它超越了之前谁的哪种观点），解释它为什么在思想史上是个"重磅炸弹"。不做通俗敷衍的解释，必须触及概念在原著中的本质。
- **底层逻辑剖析**：不追求对专业术语的回避，相反追求学术精确性。必须使用该哲学家核心的专业术语（如：否定性、异化、辩证运动、匮乏、实在界等），但在每个术语背后，必须用极具穿透力和推演性的语言将其剖析清楚。展现该概念内部的自我矛盾与必然的逻辑推演过程。
- **[强制] 拉康数学元标准化 (Mathemes)**：
    系统已集成 **KaTeX** 渲染引擎，文中所涉及的拉康公式与符号必须使用标准的 LaTeX 数学元格式，以便在前端正确渲染出标准的拉康学术符号：
    - **行内公式**：使用 `$...$` 包裹（如 `$\$$`, `$a$`）。
    - **独立块公式**：使用 `$$...$$` 包裹。
    - **常用数学元对照表**：
        - **分裂主体**：`$\$$`
        - **对象小a**：`$a$`
        - **大他者**：`$A$`
        - **大他者划杠**：`$\bar{A}$` 或 `$S(\bar{A})$`
        - **欲望指向符 (Diamond)**：`$\diamond$`
        - **能指与所指**：能指用 `$S$`，所指用 `$s$`
        - **主人能指与知识**：`$S_1$` 与 `$S_2$`
        - **象征/想象性菲勒斯**：`$\Phi$` / `$\phi$`
- **语言风格**：庄重、深邃、带有本体论的悲剧感或史诗感。语气要极度客观、冷峻，如同一份发黄的绝密学术档案。

---

### Part 2：拓扑类比与案例（`## 类比` 区块）

**重点：结构同构、主体性剥离、算法化深潜。**

> 要求：**不少于 1500 字**。严禁用死板的物理逻辑进行说教，必须通过三个维度的平衡案例，将抽象哲学具象化为一种**“不可逃逸的存在状态”**。此部分保持通用分析语境，严禁引入迷雾学派内部创作术语。

**核心原则：主体化与非人性的辩证**。案例必须描述主体在特定结构中的**感官异化、存在不可能性或被动性**，而非客观对象的简单堆叠。

**[强制] 案例结构与命名（必须严格遵守以下三个类别的命名格式）：**

1. **### 1. 文化现象： —— [具体现象名称]**
   - **重点**：揭示消费主义、数字流量或娱乐奇观之下的“强迫性语法”。 
   - **标准参考**（见 `l_unconscious_language`）：**算法短视频流**。揭示用户如何从“挑选者”被异化为“点击废料”，欲望如何被非线性能指链条彻底格式化。
2. **### 2. 现实生活：—— [社会场景名称]**
   - **重点**：深入权力博弈、社交伦理或现代管理的冰冷底座，将其**主体化**（即详述主体在其中的无力感与符号性阉割）。
   - **标准参考**：**官僚科层制中的“ID 异化”**。详述个体如何被缩减为档案编号，领会由于这种“非人称逻辑”推演出的命运必然性。
3. **### 3. 影视文学：—— [作品名] 的 [核心逻辑] 拆解**
   - **重点**：深潜经典文本，拆解其叙事弧光如何与哲学词条形成**拓扑同构**。
   - **标准参考**：**《盗梦空间》的潜意识逻辑建模**。通过梦境的“建筑学语法”，揭示无意识如何作为一个可被植入、被运算的冷酷网格而存在。

**撰写提示**：避免通俗读物式的“浅白比喻”。由于迷雾学派追求的是一种**“降维打击”式的穿透力**，请确保类比能让读者意识到，这种哲学概念此刻正像幽灵一样操纵着他们的生活边界。

---

### Part 3：迷雾学派创作理论应用（`## 应用` 区块）

**重点：理论如何驱动 M-S 公式运作。**

> [!IMPORTANT]
> **硬约束（Hard Constraints）**：此区块总字数 **不少于 1200 字**。为了确保哲学理论能直接转化为创作驱动力，撰写时必须 **强制包含以下四个子区块**，且每个子区块均需以 `####` 四级标题标识：

#### 1. 能指映射：M-S 动力学解构
阐述该概念在 **`Story = (M1 + M3) / M4 * M5`** 公式中的拓扑位置。AI 需明确以下能指在当前词条语境下的具体含义：
- **M1 (缺失主体)**：主体的核心匮乏如何被该概念定义？
- **M3 (欲望幻象)**：该概念如何规定了诱饵/对象 $a$ 的呈现形态？
- **M4 (大他者阻断)**：结构性阻力如何体现该哲学的逻辑？
- **M5 (行动驱力)**：主体对抗阻断的动作烈度与坚持姿态。
- **M6/M7 (代价与落点)**：最终的符号性后果与哲学重构。

#### 2. 视差之见：污迹的可视化部署
说明该理论如何制造 **“污迹（The Stain）”**：即如何在类型片（面具）的完美表象上，撕开一道符合特定哲学逻辑的裂痕。
- **指令**：给出具体的视觉/构图/光影指导。如何触发 **“视差之见（Parallax View）”**，让观众在瞬间瞥见那个“虚无的实在界”？

#### 3. 叙事共振：文本印证与考古
**通过具体的文本拆解，证明该理论在叙事体系里的真实效能。**
- **结构推演**：分析概念如何在公式变量间产生联动。
- **经典文本溯源**：必须结合 **至少两部经典电影** 或文学名著，拆解该词条在其中的叙事核能。

#### 4. 影像转译与叙事显影：从理论到创作的升华
提供 **专为该哲学概念量身定制的呈现逻辑**。这不是僵死的硬性指令，而是引导创作者如何通过叙事的偏离与视角的转换，让抽象的哲学如幽灵般在影像中自然“显影”。

- **呈现路径**：为了精准体现该概念，叙事应当通过何种独特的组织方式，使哲学内核从情节的缝隙中溢出？（例如：通过冗余的细节、刻意的沉默或循环的结构来呼应该概念的本质）。
- **差异化捕捉**：在处理此类母题时，本词条所提供的视角应如何区别于常规美学？如何通过影像的“异常”处理（如色调的极度偏差、构图的故意失衡）来制造概念的辨识度？
- **动态干预**：明确概念如何随着 **“步数模型（M2 → M6）”** 的推演，逐步干扰、重构并深化读者的感知预期。

## 5. 标准化执行流程（AI 工作流）

当你被要求"帮我补充 [XXX] 词条"时，请按以下顺序执行：

### 步骤一：阅读核心文档

必须先阅读 `docs/MIST_SCHOOL_THEORY_OVERVIEW.md`，确保理解迷雾学派的底层逻辑。

### 步骤二：在索引文件注册词条

编辑 `/data/codex/philosophy_refined.ts`，在对应哲学家的 `concepts` 数组中插入新词条对象（含 `id`、`name`、`enName`、`category`、`shortDef` 等字段）。

### 步骤三：创建 Markdown 草稿文件

**在 `codex-drafts/[哲学家]/[词条ID].md` 创建文件**，按照本指南第3节的 Markdown 格式撰写三个区块（定义 / 类比 / 应用），总字数不低于 5000 字。

> ⚠️ **严禁直接写 JSON 文件**。JSON 中内嵌 Markdown 长文本需要手动转义所有换行符（`\n`）和引号，极易引入格式错误导致词条页面空白。统一使用 Markdown 草稿工作流。

### 步骤四：转换为 JSON

运行以下命令，将草稿转换为系统所需的 JSON 格式：

```bash
npm run codex:build
```

### 步骤五：输出报告

告知用户：
- 索引已在 `philosophy_refined.ts` 中注册
- Markdown 草稿已创建于 `codex-drafts/[哲学家]/[词条ID].md`
- JSON 已生成至 `public/data/codex/[哲学家]/details/[词条ID].json`
- 提示刷新页面即可在迷雾辞典中查看词条

## 6. 常见错误与排查

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 词条页面空白 | JSON 格式错误（多余引号、未转义控制字符） | 删除 JSON，重新从 Markdown 草稿生成 |
| 词条不显示在列表 | 未在 `philosophy_refined.ts` 注册 | 在对应 `concepts` 数组中添加索引对象 |
| 转换后内容缺失 | Markdown 文件缺少 `## 定义` / `## 类比` / `## 应用` 标题 | 检查三个区块标题是否使用 `##` 二级标题 |
| LaTeX 符号报错 | JSON 中的 `\forall`、`\exists` 等 LaTeX 转义未处理 | 使用 Markdown 草稿写作，脚本会自动处理；或在 JSON 中写成 `\\forall` |
| 词条 ID 不匹配 | Markdown 文件名与索引 `id` 字段不一致 | 确保 `codex-drafts/lacan/文件名.md` 的文件名等于索引中的 `id` |
