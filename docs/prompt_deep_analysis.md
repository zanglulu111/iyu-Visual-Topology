## 一、七大结构性问题

### 🔴 问题 1：注意力经济的灾难性浪费 — "头重脚轻"

> [!CAUTION]
> 这是**最致命**的问题。整个 Prompt 的信息密度分配严重失衡。

**现状**：System Bible（静态宪法） ≈ **3000+ 字**，Dynamic Task（动态指令） ≈ **2000+ 字**。总量约 **5000-6000 字**。

**问题核心**：LLM 的注意力机制存在 **"首尾偏好 (Primacy & Recency Effect)"**。中间段落的指令极容易被稀释遗忘。而当前 Prompt 的结构是：

```
[3000字的抽象宪法/教学/案例] ← AI 在这里注意力最旺盛
           ↓ 渐弱...
[2000字的实际任务/具体DNA] ← AI 在这里注意力最薄弱
```

**致命后果**：
- AI 把最宝贵的注意力花在了"理解教程"上，而不是"执行具体任务"
- System Bible 中大量的 **Case Study 和教学示例**（如螺丝钉、义体的三种语境融合演示）对于一个已经理解了规则的模型来说是**纯冗余噪音**
- 真正需要 AI **死死咬住**的东西（M0 精神拓扑的具体临床逻辑、当前 DNA 序列、M4X/M5X 的视差张力）反而被挤到了注意力的尾端

**对比 codex 理论**：
> 4_04_1 明确指出："大语言模型在阅读这长达数千字的 Payload 时，极容易触发'遗忘'和'平庸化漂移'（上下文丢失）。为了防止设定崩盘，引擎通过拦截机制，给第三级火箭（Force Directives）内部打上了不可违抗的硬度级别：🚨 CRITICAL / ⚠️ HIGH / 👁️ NORMAL"

当前 Prompt **完全没有**实现这套注意力权重分级系统。所有指令都是同等权重的平铺文本，没有任何 `[CRITICAL]` / `[HIGH]` / `[NORMAL]` 标记。

### 🔴 问题 2：信息架构违反"四级火箭"原则 — 层级混乱

**codex 定义的四级火箭**：
1. 🚀 **第一级**：全域系统宪法（静态装甲）— 美学底色和红线禁忌
2. 🚀 **第二级**：用户组件清单（变量声明）— 具体的 M0-M7 和 SUR 标签
3. 🚀 **第三级**：底层硬指令列表（Force Directives）— `IF...THEN` 伪代码
4. 🚀 **第四级**：反向解码引擎（输出格式）— JSON 结构约束

**当前 Prompt 的实际结构**：
```
SYSTEM BIBLE (混合了第一级+第二级的教学内容)
  ├── 命名协议 ← 第一级 ✅
  ├── 视觉美学 ← 第一级 ✅
  ├── 核心公式 + Case Study ← 第一级，但混入了大量教学（冗余）
  ├── 铁律 ← 第一级 ✅
  ├── 代数协议 + 拓扑权重 + 时代降维 ← 第一级，但与第三级功能重叠
  ├── 风格逻辑 ← 第一级 ✅
  └── 面具协议 ← 第一级 ✅

DYNAMIC TASK (混合了第二+三+四级)
  ├── 动态转译指令 ← 第三级的雏形，但太弱
  ├── 形式律法 ← 第四级 (输出约束)
  ├── 禁用词表 ← 第一级的延伸
  ├── DNA 序列 (标签清单) ← 第二级 ✅
  ├── M0 心理协议 ← 第三级 (Force Directive)
  ├── 体量协议 ← 第三级
  ├── 世界法则 ← 第三级
  ├── 叙事质量控制 ← 第一级的重复
  ├── 三重镜头选项 ← 第四级 (输出格式)
  └── JSON 格式 ← 第四级 ✅
```

> [!WARNING]
> **核心问题**：第一级和第三级的内容严重混淆交叉，没有清晰的物理分隔。AI 无法区分"这是永恒的美学原则"和"这是本次必须死死执行的硬指令"。

### 🔴 问题 3：第三级火箭（Force Directives）严重缺失

**这是与 codex 理论偏差最大的地方。**

codex 4_04_2 明确指出第三级是"致命的执行动力炉"，应该包含从词条 `patch` 中提取的 `IF...THEN...` 强制逻辑。例如：

> `[M0_ITEM_RUNTIME]` **CRITICAL**
> IF (检测到合意) THEN (强制触发：由于不可解释的身体恶心感而产生的破坏性反驳)

**当前 Prompt 中**，第三级火箭几乎**不存在**：
- M0 的 Psychic Protocol 只是一个**通用的条件分支表**（IF 癔症 / IF 强迫症 / IF 妄想狂……），而不是基于**当前具体选择**的精准 Force Directive
- M4X（压迫烈度）和 M5X（驱力流速）的标签定义虽然被注入了 DNA 清单，但**没有被翻译成对 AI 的强制行为指令**
- 词条中的 `logic` 和 `patch` 字段完全没有被提取并编译为 `IF...THEN` 格式

**理想状态**（根据 codex）：
```
## 🚀 FORCE DIRECTIVES [第三级火箭]

[M0_PSYCHIC] 🚨 CRITICAL
当前精神拓扑 = [完美的门面]
→ 主体在"否认"的数学铁律下运行：他明明知道墙后是荒原，但严禁在叙事前3/4让他承认。
→ 表面维持精致假象的每一个细节（器物、对话、仪态）都必须丝丝入扣到令人窒息。
→ 只有在高潮点，天鹅绒才允许出现第一道褪色裂痕。

[M4X_PRESSURE] 🚨 CRITICAL
压迫烈度 = L5.绝对暴力
→ 大他者必须在故事中展现最高级别的合法暴力清洗。不是威胁，是物理碾压。
→ 该暴力必须具有制度性的冰冷仪式感，不是街头混战。

[M5X_VELOCITY] ⚠️ HIGH  
驱力流速 = L4.爆发/行动
→ 主角必须在某个节点彻底砸烂自己的体面保护壳。
→ 行动的形式必须是暴政式的、不可逆的——烧掉证件、公开秘密、物理摧毁某物。
```

### 🟡 问题 5：M0 协议的"通用条件表"问题

当前 Prompt 中 M0 的处理方式是一张**巨大的 IF/ELSE 分支表**：

```
IF [Ordinary Psychosis] → ...
IF [Autism] → ...
IF [Perversion] → ...
IF [Hysteria] → ...
IF [Obsession] → ...
IF [Paranoia] → ...
```

**问题**：
1. 用户本次只选了**一个** M0（比如"完美的门面"），但 AI 被迫阅读了**所有 6 种**精神结构的说明——其中 5 种完全无关
2. 这 5 种无关的分支描述白占了约 **300 字**的 Token 和注意力
3. 正确做法：在代码层面就应该**只注入当前匹配的那一条** Force Directive，而不是让 AI 自己去做条件判断

**对比 codex**：
> 4_04_1 §5 明确指出 M0 应该产生**精准的浮点数修饰器**和**唯一确定的逻辑约束**，而不是一个"请你自己选择适用哪条"的泛化菜单。

### 🟡 问题 6：缺少"张力走向判定"（NARRATIVE_ARC）的注入

codex 4_04_1 和 4_04_2 都反复强调，计算器算出的**走向判定**（BREAKTHROUGH / DEADLOCK / TRAGEDY / ANNIHILATION）是"卡在大模型脖子上最死的一把锁"，是"皇冠上的明珠"。

**当前 Prompt 中完全没有这个最关键的第三级指令。** 

虽然项目中存在张力计算器的代码（`mist_calculator.ts`），但其计算结果似乎并未被编译进 `buildNarrativePrompt` 的 Payload 中。这意味着 AI 在生成故事时，**对结局的走向（悲剧/突破/僵局）没有任何物理级别的硬约束**，全靠 M7 标签的文学性暗示来引导——这是远远不够的。

---

### 🟡 问题 7："三重镜头"输出模板的结构性问题

三个 Option（结构主义/后结构/实在界）的描述目前是**硬编码在 Prompt 中的纯文本**，每个 Option 的指令几乎完全一样，只换了几个形容词（"专业的" vs "私密的" vs "萦绕的"）。

**问题**：
1. 三个 Option 的区分度太弱——AI 容易生成三个仅在措辞上略有不同但在结构上同质化的方案
2. 缺乏对每个 Option 的**具体执行约束**（比如：Option 1 的 M4 必须是外部具象力量、Option 2 的 M4 必须是内在关系）虽然有写但太弱，没有用 `[CRITICAL]` 等标记来强制

## 三、最适合 AI 的 Prompt 到底是什么样的？

### 3.1 核心原则：**金字塔倒置法**

```
┌──────────────────────────────────────┐
│  🚨 CRITICAL: 本次必须死死咬住的 3-5 条铁律  │  ← AI 注意力最强
│  （M0 精准逻辑、NARRATIVE_ARC、M7 宪法）     │
├──────────────────────────────────────┤
│  ⚠️ HIGH: 本次 DNA 序列 + Force Directives  │  ← 具体执行层
│  （M4X/M5X 的 IF→THEN、时空坐标锁定）        │
├──────────────────────────────────────┤
│  📋 NORMAL: 标签清单 + 世界法则              │  ← 素材层
├──────────────────────────────────────┤
│  📖 REFERENCE: 宪法精要（精简到极致）          │  ← 背景知识
│  （去掉一切案例，保留纯规则句）               │
├──────────────────────────────────────┤
│  📤 OUTPUT: 输出格式 JSON                    │  ← 最后执行
└──────────────────────────────────────┘
```

### 3.2 具体改进路线图

#### 🔴 P0 级（必须做）

1. **精简 System Bible 至 1500 字以内**
   - 删除所有 Case Study（螺丝钉的三种语境、义体的两种语境等）
   - 合并所有重复条目（"严禁学术腔"只写一次）
   - 将教学性文本替换为纯规则性短句

2. **实现注意力权重标记系统**
   - 在 Force Directives 前添加 `🚨 CRITICAL` / `⚠️ HIGH` / `👁️ NORMAL` 标签
   - 将 M0、M7、NARRATIVE_ARC 标记为 CRITICAL

3. **M0 精准注入**
   - 在代码层（`narrativeGenerator.ts`）中，根据用户选择的具体 M0 标签，只注入**对应的那一条**精准指令
   - 删除通用条件分支表

#### 🟡 P1 级（应该做）

4. **提取词条 `logic` 字段编译为 Force Directives**
   - 从 M4X、M5X、SUR4X、SUR10X 等调音台标签的定义中，提取关键约束
   - 编译为 `IF...THEN` 格式的伪代码指令
   - 标记为 `⚠️ HIGH`

5. **注入张力走向判定**
   - 将计算器的 NARRATIVE_ARC 结果（如 DEADLOCK、TRAGEDY）编译为 `🚨 CRITICAL` 级指令
   - 格式：`[NARRATIVE_ARC] 🚨 CRITICAL: 走向判定 = 僵局(DEADLOCK)。保持极大戏剧张力，终幕前不得解决冲突。`

6. **三重镜头模板的差异化加强**
   - 为每个 Option 注入独特的、不可替代的执行约束
   - Option 1：M4 必须是可物理触碰的外部力量，禁止内心独白超过 20%
   - Option 2：M4 必须是关系性或内在的，必须包含至少一段主观意识流
   - Option 3：环境描写必须占比 40% 以上，人物对话压缩到最低

#### 🟢 P2 级（锦上添花）

7. **动态 KV Cache 优化**
   - 将真正"永远不变"的规则集中写死为一个极短的纯静态文本
   - 将所有动态内容集中在一起，利用 LLM 的 KV Cache 机制最大化缓存命中率

8. **建立"代价配平"校验指令**
   - 根据 codex 4_04_1 的 `PriceVerdict` 逻辑，当 M6 代价与张力不匹配时注入强制校验
   - `IF (张力 > 10 && M6 代价 < L3) THEN: 代价失衡异常！必须翻倍偿还。`

## 四、一句话总结

> **当前 Prompt 的核心问题不是内容不对，而是信息架构不对。**
> 它像一本写给人类学生的教科书，而不是一封写给冷血算力引擎的精准指令信。
> 需要做的不是"加更多规则"，而是**"用更少的字说更狠的话，并且把最狠的话放在最前面"**。
