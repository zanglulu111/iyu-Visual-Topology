## 五、 v3.0 词条格式与场域描写示例 (Field Description Examples)

> [!TIP]
> **开发指南**：本节展示了 v3.0 场域描写风格如何将精神结构定义降维映射到 AI 的动力学内核。注意：所有示例均来自实际词库数据文件。

### 5.1 词条数据结构 (LibraryItemDef)

每条词条包含以下字段：

| 字段 | 说明 | 示例 |
| :--- | :--- | :--- |
| `id` | 唯一标识符 | `os_the_questioning_gaze` |
| `name` / `nameEn` | 词条标题 | 质询回路 / The Questioning Loop |
| `group` / `groupEn` | 所属子类型 | A1. 神经症-癔症 (Hysteria) |
| `def` / `defEn` | 一句话定义（~50字） | "主角的世界围绕一个永远得不到回答的问题旋转" |
| `core` / `coreEn` | 场域描写（~150字高张力基线） | 以"主角"为锚点的拓扑描写 |
| `reference` / `referenceEn` | 文学/电影/精神分析引用 | 跨学科参引 |

### 5.2 A1 癔症示例：质询回路 (The Questioning Loop)

*   **def**："主角的世界围绕一个永远得不到回答的问题旋转——'你到底想要我怎样？'"
*   **core**："在主角的世界里，每一段关系都是一场审讯——不是他在审问别人，而是在逼迫对方说出'你对我来说意味着什么'。他活在回音壁里，所有声音都被折射成同一个问题。没有回答能让他满足，因为一旦有了答案，问题就消失了——而问题本身就是他存在的全部理由。沉默是他最无法忍受的声音：它意味着他可能根本不值得被回答。"
*   **reference**：陀思妥耶夫斯基《白痴》中娜斯塔霞；伍迪·艾伦《安妮·霍尔》。

### 5.3 C4 普通精神病示例格式说明

普通精神病词条的场域描写同样遵循"主角锚定"原则，但增加了**微妙的"接缝感"**——描写主角表面正常的生活下，那些几乎不可察觉的拓扑裂隙。

### 5.4 与旧版"算法补丁卡"的对比

| 维度 | 旧版 v2.0（算法补丁卡） | 新版 v3.0（场域描写） |
| :--- | :--- | :--- |
| **格式** | 力学修正 + 渲染补丁 + 运行判定 | def + core + reference |
| **语言** | 算法式参数定义 | 主角锚定的拓扑散文 |
| **功能** | 给 AI 执行逻辑 | 给 AI 提供"引力场模板" |
| **张力** | 单色（偏黑暗） | 双面（A面/B面）隐含于 core 的弹性中 |

## 六、 方法论与操作红线 (Methodology & Constraints)

### 6.1 场域描写校准原则

配置 M0 词条时，必须检查：

1.  **是否锚定于"主角"？** 如果一条描述可以适用于任何人，说明它太抽象了。每条 core 都必须让读者立即感受到"这是某个特定的人站在某个特定的拓扑位点上"。
2.  **是否避免了因果预设？** core 描述的是"场域的弯曲方式"，不是"角色接下来会怎样"。严禁出现"如果……那么……"的因果逻辑。
3.  **是否保持了~150字的高张力基线？** 太短则缺乏沉浸感，太长则张力稀释。
4.  **是否包含跨学科引用？** 每条词条必须包含至少两个来自文学、电影或精神分析经典案例的引用，以维持迷雾学派的叙事深度。

### 6.2 M0 对下游模块的引力扭曲规则

*   **M0 → M1**：M0 决定了 M1 的"空洞"被体验的方式（神经症式的焦虑 vs 精神病式的碎裂 vs 倒错式的否认）。
*   **M0 → M2**：M0 决定了 M2 的"穿刺"如何被系统吸收（意义回锁 vs 系统蓝屏 vs 物理磨损 vs 边界崩坏）。
*   **M0 → M5**：M0 决定了 M1 到 M5 的转化效率（<30% vs ≈100% vs 非线性脉冲 vs 零外输出）。

### 6.3 关于"结构迁移"的终极禁令

M0 严禁出现以下叙事：

*   ❌ "他曾经是强迫症结构，但经历了一场创伤后变成了癔症结构。"
*   ❌ "她通过治疗从精神病结构'恢复'为神经症结构。"
*   ✅ "他在强迫症结构的拓扑内部，经历了一次结构性爆炸——强迫的仪式彻底失效，但他没有'变成'别的结构，而是在废墟中发现了强迫症结构最深层的逻辑：他就是那个仪式本身。"
